01 / DATA FLOW

From research files to queryable data.

BIDS TSV and JSON files supply the data. Three schemas preserve its origin, integrate its meaning and prepare it for analysis.

  1. 1 / PRESERVE

    ucla_raw

    Original records, JSON dictionaries and file hashes keep every value traceable.

  2. 2 / CONFORM

    ucla_core

    The same source records become shared dimensions and facts with explicit keys and grains.

  3. 3 / SUMMARIZE

    ucla_mart

    Five SQL views aggregate the core model for cohort, coverage and score analysis.

How I orchestrate it

Manual CLI run: repeatable local builds, followed by a one-time PostgreSQL initialization.

  1. Build locally. Python creates raw/core data in DuckDB and validates identities, keys and counts.
  2. Export a contract. CSV files and a manifest carry column definitions, row counts and SHA-256 checksums.
  3. Load Neon. The Node importer verifies the handoff, loads raw/core and creates mart views in one PostgreSQL transaction.
  4. Explore. The Vercel API connects with a SELECT-only reader; this page queries all three schemas.

Raw and core are built from the same ingested files. Mart views read core tables. MRI binaries remain in file storage.
